/**
@mainpage L0_format

@section Synopsis

\verbatim
   L0_format [param-file]
\endverbatim

@section Description

\c L0_format reads Level 0 data product files generated in the IOC and
re-writes these data in netCDF4/HDF5 formatted files suitable for
archiving and for further data processing.  By default, the input data
product files are deleted after they are read.

@section param_file Parameter file

\c L0_format is controlled by a parameter file that may be
provided as an optional command-line argument.  If no parameter
file is specified on the command-line, \c L0_format reads
\c l0_format.cfg from the current directory.

Here is an example parameter file:
\verbatim
format_version = "1.0";

main: {
   incoming_dir = "/vex/d0/tmp/ioc_sdpc_interface/ioc_out";
   input_filename_glob_pattern = "tempo_d*.???";
   tpinfo_file = "/tmp/tempo_tpinfo_r6.csv";
   monitor_wait_secs = 30.0;
   daemon_logfile_path = "/vex/d0/tmp/ioc_sdpc_interface/l0.log";
};

tpsec: {
   processing_version = 1;
   output_dir = "/vex/d0/tmp/ioc_sdpc_interface/hk";
   outfile_deltat_sec = 300.0;
};

exprec: {
   processing_version = 1;
   output_dir = "/vex/d0/tmp/ioc_sdpc_interface/exprec";
   outfile_capacity = 128;
};
\endverbatim

In addition to the parameter file format version number, the parameter
file contains several parameter groups which are described in the
following sections.

@subsection main Main parameter group

The main parameter group contains the following parameters:
  \li \c incoming_dir  Path to the directory receiving L0 data files
            from the IOC.

  \li \c input_filename_glob_pattern  Globbing pattern used to
            identify the file basenames used for incoming L0 data
            files from the IOC.

  \li \c tpinfo_file Path to CSV format file containing metadata
         that describes each telemetry point.  The metadata provides
         a description, units, data type, etc. for each telemetry point.

  \li \c monitor_wait_secs Specifies how long \c L0_format should wait
         before checking \c incoming_dir for new input files.

  \li \c daemon_logfile_path Path to the file that is to receive run-time 
           log messages generated by \c L0_format when running as a
            daemon.

@subsection tpsec Telemetry point section files

  \li \c processing_version Processing version number for netCDF4/HDF5 output files.

  \li \c output_dir Path to directory where output files should be written.

  \li \c outfile_deltat_sec  Input data files with timestamps separated
by no more than \c outfile_deltat_sec may be merged into a single
output file.

@subsection exprec Exposure records

  \li \c processing_version Processing version number for netCDF4/HDF5 output files.

  \li \c output_dir Path to directory where output files should be written.

  \li \c outfile_capacity The maximum number of exposure records of a
      given type that may be stored in a single output file.  The
      following exposure record types are supported: dark, irradiance,
      radiance, linearity-dark, linearity-irradiance.

@section design_choices Design Choices

@subsection exprec Exposure records

Exposure records are packed into netcdf files that contain a fixed
maximum number of exposure records, e.g. 128. A new exposure record
file is created either when the existing exposure record file is
filled, or when a new exposure record type is encountered in the
time-ordered incoming data stream.

This introduces no significant additional costs in processing time or
disk space. When images are initialized with fill values and when
output files use chunking and compression appropriately, unused space
compresses quite well and the amount of wasted disk space is
minimized. On the other hand, creating output files that contain a
custom number of images requires iteration, complicating the
processing logic.

@subsection tpsec Telemetry point section files

The contents of telemetry point section files are not split across
netCDF files. Each netCDF file contains data from telemetry point
section files with start times separated by no more than \c
outfile_deltat_sec.

This eliminates the logic associated with splitting input section
files across multiple output netcdf files.

*/
