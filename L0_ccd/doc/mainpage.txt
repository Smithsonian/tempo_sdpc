/**
@mainpage L0_ccd

@section Synopsis

@verbatim
Usage: L0_ccd [options] <input-file>
  Required:
   -d | --dark FILE       Input corrected dark current file
   -i | --instr FILE      Instrument telemetry points file.
                          Provide a list using FILE=@DIR/paths.lis.
                          When FILE provides a directory path,
                          files matching hk_glob_pattern are examined
                          (hk_glob_pattern is defined in the config file)
   -o | --output FILE     Output file
  Optional:
   -b | --bpix FILE       Bad pixel file
   -c | --config FILE     Configuration file
   -n | --num N           Process <= N exposure records
   -v | --verbose lev     Logging level
@endverbatim

@section Description

\c L0_ccd applies radiometric and dispersed wavelength calibrations to
TEMPO Level 0 CCD data. The following sections describe the support
for processing different types of input data. Depending on the input
data, the primary output products are corrected dark current images,
dark current lookup tables, Level 1 radiance granules, and Level 1
irradiance granules.

@subsection l0_ccd_dark Dark frames

@verbatim
Usage: L0_ccd --instr <level0-tpinfo> --output <dark-table> \
              <level0-dark-granule>
@endverbatim

The dark frames in the input granule are used to construct a lookup
table based on the \a ordered_by sort key specified in the \a
dark_table_creation section of the \ref param_file. A uniform grid of
sort key values is defined so as to span the range of sort keys
appearing in the input granule.  After correcting the dark frames in
the input granule, the corrected frames are sorted and binned on the
sort key grid.  The output dark table contains the sort key grid and
the mean dark current for each grid point.

In the output file containing corrected dark frame images, the pixel
values are arranged so that the spatial index (serial readout) varies
fastest, the wavelength index (parallel readout) varies next fastest,
and the exposure number varies slowest.  This pixel ordering is
consistent with the pixel ordering in the Level 0 exposure record
granules and simplifies dark subtraction.

@subsection l0_ccd_irr Irradiance exposures

@verbatim
Usage: L0_ccd --instr <level0-tpinfo> --dark <dark-table> \
              --output <level1-irr-granule> <level1-irr-granule>
@endverbatim

In the Level 1 irradiance file, the irradiance pixel values are
arranged so that the wavelength index varies fastest, the pixel index
along the slit varies next fastest, and the exposure number varies
slowest. This pixel ordering is most convenient for subsequent
processing.

@subsection l0_ccd_rad Radiance exposures

@verbatim
Usage: L0_ccd --instr <level0-tpinfo> --dark <dark_table> \
              --output <level1-rad-granule> <level1-rad-granule>
@endverbatim

In the Level 1 radiance file, the pixel values are arranged so that
the wavelength index varies fastest, the spatial (cross-track) index
varies next fastest, and the mirror step varies slowest.  This pixel
ordering is most convenient for subsequent processing.

@subsection l0_ccd_linearity Linearity calibration

@verbatim
Usage: L0_ccd --instr <level0-tpinfo> --output <dark-table-lin> \
               <level0-dark-granule>
@endverbatim

Processing of dark frames for linearity calibration may differ in some
respects from the processing of dark frames intended for routine
observations.  While the accumulated total number of dark counts is
expected to be proportional to the integration time, the dark current
itself may also depend on the integration time. For example, the dark
current might accumulate at a rate that is sensitive to the total
charge in each pixel.  In this case, it may be useful to use
integration time as a sort key to construct the dark table for
linearity calibration.  In contrast, the dark table for routine
operations is likely to use either temperature or the storage region
dark current as a sort key.

@verbatim
Usage: L0_ccd --instr <level0-tpinfo> --dark <dark-table-lin> \
              --output <level1-irr-granule-lin> <level1-irr-granule-lin>
@endverbatim

Processing of irradiance frames for linearity calibration is
essentially identical to routine irradiance processing.
