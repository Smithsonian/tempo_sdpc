@mainpage plan

@section Synopsis

\verbatim
Usage: plan [options]
  Optional:
   -h | --help              Print this usage message
   -d | --date YYYY-MM-DD   Plan start date
   -n | --ndays NUM         Number of days to plan [default=14]
   -o | --output FILE       Output file [default=stdout]
   -s | --scan METHOD       METHOD = std | opt1 [default=std]
   -c | --config FILE       Configuration file
   -m | --master            Generate master scan table, then exit
   -z | --szaout FILE       Generate netCDF output to help visualize
                            the solar zenith angle at selected times
\endverbatim

@section Description

\c plan can be used to generate a TEMPO Earth scan plan or a TEMPO
master scan table for input to the TEMPO Instrument Operations Center
(IOC). The master scan table is likely to remain fixed for the
duration of the mission.  Earth scan plans are likely to be updated
weekly or even more frequently, as needed.

Earth scan start and stop times are determined by the solar zenith
angle (SZA) at two control points.  The eastern control point
determines the start time of the first scan of each day.  The western
control point determines the start time of the last scan each day.
Scans are planned to continue as long as the SZA is smaller than the
maximum value, \c max_sza, specified in the parameter file.

The following scanning methods are currently supported:

\li \e std: The \e std scan method uses a single mirror scan table to
scan from the eastern scan limit (\c scan_beg) to the western scan limit
(\c scan_end) each day.

\li \e opt1: The \e opt1 scan method uses three mirror scan tables
each day. One scan table covers the eastern half of the field of
regard (FOR) and is used during the morning.  Another table covers the
western half of the FOR and is used during the late afternoon.  The
other table is using during mid-day when the entire FOR is suitably
illuminated.

@section param_file Parameter file

\c plan is controlled by a parameter file that may be provided as an
optional command-line argument.  If no parameter file is specified on
the command-line, \c plan reads \c plan.cfg from the current
directory.

The parameter file contains several parameter blocks, as follows:
  \li \c scan_config: Coordinates of scan endpoints, and control points;
                      scan timing parameters
  \li \c limits_config:  Other parameter limits that constrain scans
  \li \c sat_config:  Satellite and instrument pointing geometry
  \li \c iers_config: Earth orientation and time scale parameters
  \li \c novas_config: Solar system ephemeris
  \li \c master_table_config: Parameters defining the master scan table
  \li \c output_sza_map_config: Parameters used to generate a solar
         zenith angle map (for visualization only)

Here is an example parameter file:
\verbinclude plan.cfg.example

@section vis_section Visualization

For planning purposes, the INR library interface provides a mapping
from coordinates on the Earth's surface (longitude, latitude), to
angular coordinates in the field of regard (azimuth, elevation). This
interface is used to assign mirror step angular coordinates to the
start point of each scan.

For visualization purposes, the inverse mapping is most convenient,
mapping each pixel in the field of regard to a point on the Earth's
surface. The \c proj4 library is used to provide this mapping through
the library's tilted perspective projection (\e tpers), using the
parameters specified in the \c output_sza_map_config block of the
parameter file. To ensure that the visualization accurately matches
the TEMPO field of regard, it's important that the parameters in the
\c output_sza_map_config block reflect the actual instrument
configuration.
