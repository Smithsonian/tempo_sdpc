@section inr_post_synopsis Synopsis

\verbatim
Usage: L1_inr_post [options] <input-file>
  Required:
   -s | --snow FILE       snow and ice mask file
  Optional:
   -c | --config FILE     configuration file
   -v | --verbose lev     logging verbosity
\endverbatim

@section inr_post_description Description

\c L1_inr_post modifies a geolocated Level 1 radiance file to apply
geolocation-dependent corrections and to populate file variables that
depend on geolocation.

@section snow Snow and Ice cover

Snow and ice cover information is obtained from the IMS Daily Northern
Hemisphere Snow and Ice Analysis 1km resolution data set from the NASA
National Snow and Ice Data Center Distributed Active Archive Center
(NSIDC DAAC).

The IMS snow product labels each pixel as either outside the coverage
area (0), sea (1), land without snow (2), sea ice (3), or snow covered
land (4).  For each TEMPO pixel, \c L1_inr_post computes the fractional
area of that pixel covered by IMS product pixels labeled as 3 or 4.
The fractional area covered by snow and/or ice is written to the
\c snow_ice_fraction variable in the geolocated radiance file.

The snow data product file name must be provided on the command line.

In addition to the parameter file format version number, the parameter
file contains several parameter groups which are described in the
following sections.

@subsection ground_pixel_quality_flags Ground pixel quality flags parameter group

The ground_pixel_quality_flags parameter group contains the following parameters:

  \li \c max_glint_angle_deg For each point on the earth's surface,
the glint possibility flag is set when the satellite viewing
angle at the surface point lies within a cone of radius \c max_glint_angle_deg
centered on the nominal reflected sunlight vector.

  \li \c max_eclipse_angle_deg For each point on the earth's surface,
the solar eclipse flag is set when the angular separation of the moon
and the sun as viewed from the surface point is smaller than \c
max_eclipse_angle_deg.

@subsection elevation Elevation parameter group

Elevation data are assumed to be provided in non-overlapping \c
geotiff formatted tiles which may be arranged either in a grid or in
latitude bands.  One set of tiles should provide the mean elevation
within each pixel.  Another set of tiles should provide the standard
deviation of the elevation within each pixel.

  \li \c tile_layout  Supported values are \c grid and \c latitude_bands.

  \li \c tiles_mean  This parameter is an array of strings containing
the full path to each geotiff mean elevation tile.  Paths may
incorporate references to environment variables.

  \li \c tiles_stddev This parameter is an array of strings containing
the full path to each geotiff elevation standard deviation tile.  Paths may
incorporate references to environment variables.

It is assumed that corresponding files in the two lists, \c tiles_mean
and \c tiles_stddev, have precisely the same pixel boundaries and
geographic coverage, but this correspondence is not checked at
run-time.

@subsection land_cover Land cover parameter group

Land cover data are assumed to be provided in non-overlapping \c
geotiff formatted tiles which may be arranged either in a grid or in
latitude bands.  Two sets of tiles must be provided, containing MODIS
land cover Type 1 and MODIS land cover Type QC classification data,
respectively.

  \li \c tile_layout  Supported values are \c grid and \c latitude_bands.

  \li \c tile_type1  This parameter is an array of strings containing
the full path to each geotiff land cover type 1 tile.  Paths may
incorporate references to environment variables.

  \li \c tile_typeQC This parameter is an array of strings containing
the full path to each geotiff land cover type QC tile.  Paths may
incorporate references to environment variables.

It is assumed that corresponding files in the two lists, \c
tiles_type1 and \c tiles_typeQC, have precisely the same pixel
boundaries and geographic coverage, but this correspondence is not
checked at run-time.

@section design_choices Design Choices

@subsection gmted_elevation Elevation data

Using the GMTED elevation data files directly means that there's no
need to reformat or regrid the GMTED data, eliminating the need to
develop, test, document, and maintain the code to perform such
functions.

The terrain height value assigned to each TEMPO pixel is the overlap
area-weighted mean of the GMTED pixels that overlap the TEMPO pixel.
While database pixel-lookups are convenient in native
longitude-latitude coordinates, pixel overlap area computations are
most convenient in coordinates defined by the Albers equal-area
projection (for details, see the documentation for \c L2_regrid).
Albers coordinates are computed using the \c proj4 library.

@subsection modis_land_cover Land cover data

Because the native sinusoidal projection (SIN) used in the MODIS data
product tiles is inconvenient for performing pixel lookup based on
lon-lat coordinates, the MODIS data products were resampled to use the
GEO projection and the tiles were merged into latitude bands. The GEO
projection gives the simplest mapping from (lon,lat) to pixel
(column,row), and merging tiles into latitude bands avoids problems
associated with non-square tile boundaries. This resampling and
merging was done using the MODIS-provided MRT suite of tools,
specifically, \c resample, and \c mrtmosaic.

The script used to perform the resampling and mapping is included:

\verbinclude modis_mosaic.sh

@section polcorr_description Description

\c L1_polcorr modifies the radiances in a geolocated Level 1 radiance
file to apply a geolocation- and wavelength-dependent polarization
correction.  This correction attempts to remove the effect of the
instrument's polarization sensitivity, to yield a better approximation
of the total intensity of the radiance incident on the detector.

@section polcorr_param_file Parameter file

\c L1_polcorr is controlled by a parameter file that may be provided
as an optional command-line argument.  If no parameter file is specified
on the command line, \c L1_polcorr reads \c l1_inr_post.cfg from the
current directory.

Here is an example of the required control parameters:
\verbatim
polcorr_tables: {

  # instrument linear polarization sensitivity:
  #
  lps_lut = "$SDPC_REFDATA_DIR/polarization/lps_table.nc";

  # QU dependence on selected parameters:
  #
  qu_lut = "$SDPC_REFDATA_DIR/polarization/Polarization_LUT_qu_SIqu_clima_reordered.nc";

  # LUT SI "swav" wavelength grid index limits for retrievals
  waves_uv  = [ 1, 13];
  waves_vis = [14, 28];

  use_mler = true;
  merge_bands = true;
};

polcorr_instr_geom: {

# sat_lon = geostationary satellite longitude
  sat_lon = -100.0;

# tilt>0 [deg] is northward tilt of instrument boresight,
#              about spacecraft roll axis
# azi>0 [deg] is rotation, eastward from north (CW),
#             about instrument boresight axis
# These angles specify the instrument pointing direction
# for the tilted perspective projection ('tpers') from
# the Proj4 library.

   tilt = 5.53;
   azi  = 4.5;
};
\endverbatim
